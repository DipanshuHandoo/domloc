# How it works

## CSS selectors

domloc walks from the element up towards the root. For each element it emits the first
matching step:

1. **Attribute anchor** (only with the `attributes` option): the element's value for a listed
   attribute is unique in the document → `[data-testid="save"]`. The walk stops.
2. **Id anchor**: the id is unique in the document and does not match `idDenyPattern` →
   `#main`. The walk stops.
3. **First class**: the element's first class is not deny-listed and no sibling with the same
   tag has it → `div.card`.
4. **Tag**: no sibling has the same tag → `nav`.
5. **Position**: `li:nth-of-type(3)`.

Steps are joined with `>`. The walk stops below `html`, so unanchored selectors start at
`body`. `cssSelectorOf(htmlElement)` returns `html`. Ids, classes and attribute names go through
`cssEscape` (the `CSS.escape` algorithm); attribute values are written as escaped CSS strings.

### Uniqueness by construction

Each step is unique among its siblings, and the walk ends at a document-unique anchor or at
`body`. The full selector therefore matches exactly one element, and domloc never runs
`querySelectorAll`. A randomised property test in the suite checks this against jsdom and
Cheerio, and a real-Chromium test checks it in a browser.

Only the first class is considered. This is deliberate: it keeps selectors short and readable,
and the first class is usually the block or component name. When it is not usable, the
position step is used.

### Tag names

HTML tag names are lower-cased. SVG, MathML and XML elements keep their case (`foreignObject`),
because case-sensitive selector engines need it. Siblings are grouped for `:nth-of-type` by this
case-preserved name. Tag names are CSS-escaped, so prefixed tags from Word or Facebook markup
(`<o:p>`, `<fb:like>`) become `o\:p` and `fb\:like`. Custom adapters control the name through
`selectorName`.

### Quirks mode

In documents without a doctype (quirks mode), browsers match class and id selectors
case-insensitively. domloc detects quirks mode through the adapter (`document.compatMode` for
the DOM, parse5's document mode for Cheerio). It then treats `Card` and `card`, or `#Main` and
`#main`, as the same name when checking uniqueness. The emitted selector keeps the original case.

### Attribute values

For HTML attributes whose values browsers compare case-insensitively (`type`, `lang`, `dir`,
`rel`, `method` and others listed in the HTML spec), the `attributes` option counts values
without case. `type="text"` and `type="TEXT"` therefore never anchor. Other attributes,
including every `data-*` attribute, are case-sensitive.

## XPath

`xpathOf` returns an absolute, positional path in which every step has an index
(`/html/body[1]/main[1]/div[2]/a[1]`); the root `html` step has none. With
`omitFirstIndex: true`, every `[1]` is dropped.

Ordinary HTML elements use lower-case names, byte-compatible with the builders domloc replaced.
Other elements use a step that still resolves in browsers:

| Element                                                 | Step                                  | Why                                                                                                                |
| ------------------------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| HTML element                                            | `div[2]`                              | Legacy format                                                                                                      |
| SVG / MathML, or an unusual tag name (`o:p`, `x.y`)     | `*[local-name(.)='foreignObject'][1]` | In HTML documents an unprefixed name test only matches HTML-namespace elements, and `o:p` is not a valid name test |
| XML element with a namespace prefix (no namespace info) | `*[name(.)='ns:item'][1]`             | Matches the qualified name                                                                                         |
| XML element without namespace info                      | `Entry[2]`                            | Case is kept, because XML is case-sensitive                                                                        |

The explicit `(.)` argument is equivalent to `local-name()` and is also understood by jsdom's
XPath engine. Namespace information comes from the adapter's `namespace` method: the DOM
(`namespaceURI`) and Cheerio's default parser (parse5) provide it. Cheerio's XML mode
(htmlparser2) does not, so elements in a default `xmlns` namespace are addressed by name only.

## Default deny-lists

`DEFAULT_CLASS_DENY_LIST` skips classes that describe state or are generated by tooling:

| Pattern                        | Examples                                                                                                           |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Runtime state words            | `active`, `current`, `selected`, `open`, `hidden`, `visible`, `loading`, `fade`                                    |
| State prefixes                 | `is-open`, `has-icon`, `no-js`, `js-toggle`                                                                        |
| Leading digit                  | `1col`                                                                                                             |
| CSS-in-JS / framework prefixes | `css-1hwfws3` (emotion), `sc-bdVaJa` (styled-components), `jsx-123` (styled-jsx), `svelte-xyz`, `ng-star-inserted` |
| CSS Modules hash suffix        | `Button_title__a1b2c`                                                                                              |
| Long digit runs or hex tokens  | `item-12345`, `x-deadbeef42`                                                                                       |

`DEFAULT_ID_DENY_PATTERN` skips ids with a leading digit, 4+ digit runs, long hex tokens and
React `useId` values (`:r1:`, `«r1»`, `_r_1_`). Duplicate ids are never used, whatever the
pattern.

The defaults are frozen. To change them, build a new list from them (see
[Configuration](configuration.md)).

## Caching

A context holds:

- `WeakMap`s for sibling groups, per-group class counts, anchors and computed selectors/XPaths
- one id-count map and one count map per attribute, each built on first use from the whole
  document

Because the maps are weak, a context does not keep detached nodes alive. Cached results are
reused across calls, so mutating the document makes them stale. Create a new context after a
mutation.
